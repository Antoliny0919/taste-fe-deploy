# 총총 프론트엔드 배포 POC

React(webpack + pnpm) 앱을 AWS에 배포하는 **두 가지 방식**을 최소 코드로 검증하기 위한 리포지토리입니다.

> 이 POC의 목표는 딱 하나입니다.
> **"코드를 고쳐 push하면 배포된 주소에 반영되는가"** 를 눈으로 확인하는 것.
> 백엔드(Spring) 배포는 다루지 않습니다.

| 버전                       | 방식                              | 이럴 때 고른다                                             |
| -------------------------- | --------------------------------- | ---------------------------------------------------------- |
| [**버전 1 — S3**](./s3/README.md)   | 빌드 결과물을 S3 버킷에 복사        | 프론트를 백엔드와 완전히 분리하고 싶다. 관리 부담 최소     |
| [**버전 2 — EC2**](./ec2/README.md) | EC2로 전송 후 nginx가 서빙 + 프록시 | 백엔드가 이미 쓰는 EC2에 얹고 싶다. CORS·쿠키를 피하고 싶다 |

---

## 폴더 구조

```
chongchong-deploy-poc/
├── frontend/                   # 두 버전이 공유하는 최소 리액트 앱
│   ├── src/App.tsx             # ★ 배포 확인용 화면 (이 파일을 고쳐서 테스트)
│   ├── webpack.config.js       # contenthash 파일명 + 빌드 정보 주입
│   ├── package.json
│   └── ...
│
├── s3/                         # 버전 1
│   ├── README.md               # 설명 + 다이어그램 + 진행 플랜
│   ├── bucket-policy.json      # S3 퍼블릭 읽기 정책
│   └── iam-policy.json         # 배포용 IAM 최소 권한
│
├── ec2/                        # 버전 2
│   ├── README.md               # 설명 + 다이어그램 + 진행 플랜
│   ├── nginx/chongchong.conf   # 정적 서빙 + /api 프록시 + SPA 라우팅
│   └── setup-ec2.sh            # 서버 초기 세팅 (1회 실행)
│
└── .github/workflows/          # ← 워크플로는 반드시 이 경로여야 GitHub이 인식한다
    ├── deploy-s3.yml
    └── deploy-ec2.yml
```

> 워크플로 파일만 `s3/`, `ec2/` 안에 두지 못한 이유는, GitHub Actions가 **`.github/workflows/` 아래만 읽기 때문**입니다. 실제 프로젝트에서는 둘 중 채택한 하나만 남기세요. 지금처럼 둘 다 있으면 `frontend/` 변경 시 두 워크플로가 동시에 돕니다.

## 배포 방식 한눈에 비교

|                     | 버전 1 (S3)                            | 버전 2 (EC2 + nginx)                  |
| ------------------- | -------------------------------------- | ------------------------------------- |
| 배포 동작           | 파일 복사 (`aws s3 sync`)              | 파일 전송 후 심볼릭 링크 교체         |
| 프론트 주소         | 백엔드와 **다름**                      | 백엔드와 **같음**                     |
| **CORS**            | 스프링에 설정 필요                     | 필요 없음                             |
| **쿠키 인증**       | `SameSite=None; Secure` + 양쪽 HTTPS   | 그냥 동작                             |
| SPA 라우팅 처리     | 오류 문서를 `index.html`로 지정        | nginx `try_files ... /index.html`     |
| HTTPS               | CloudFront 필요                        | certbot 등으로 서버에 설치            |
| 서버 관리           | 없음                                   | nginx·보안그룹·SSH 키 관리 필요       |
| 비용                | 사실상 0에 가까움                      | EC2 인스턴스 비용 (백엔드와 공유)     |
| 롤백                | 이전 빌드 재업로드                     | 링크만 이전 폴더로 되돌리면 즉시      |
| 프론트 학습 난이도  | 낮음                                   | 중간 (서버 지식 필요)                 |
| 백엔드와의 결합도   | 낮음 (독립 배포)                       | 높음 (같은 서버, 사전 합의 필요)      |

**총총 기준 참고**: 소셜 로그인(카카오/구글/애플)을 붙일 계획이라 리다이렉트·쿠키 이슈가 생깁니다. 버전 1로 가면 CloudFront + HTTPS를 초기에 함께 붙여야 하고, 버전 2는 그 부분이 자연히 해결되는 대신 서버 설정을 프론트가 떠안게 됩니다. RN WebView에서 같은 페이지를 띄우는 구조도 오리진이 하나인 쪽이 단순합니다.

## 시작하기

### 1. 로컬 확인

```bash
cd frontend
pnpm install     # ← lockfile이 생성됩니다. 반드시 커밋하세요
pnpm start       # http://localhost:3005
pnpm build       # dist/ 확인
```

> 워크플로가 `pnpm install --frozen-lockfile`을 쓰므로 **`frontend/pnpm-lock.yaml`이 커밋되어 있지 않으면 CI가 실패합니다.**

### 2. 원하는 버전의 문서를 따라 AWS를 준비

- [s3/README.md](./s3/README.md) — 버킷 생성부터 Secrets 등록까지
- [ec2/README.md](./ec2/README.md) — 서버 세팅부터 Secrets 등록까지

### 3. POC 검증

`frontend/src/App.tsx`의 `MESSAGE` 문구를 수정하고 main에 push → Actions 초록불 → 배포 주소 새로고침. 문구와 커밋 해시가 바뀌어 있으면 CD가 동작하는 것입니다.

## 이 POC가 일부러 넣어둔 장치

| 장치                         | 이유                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| 화면에 커밋 해시·빌드 시각 표시 | "반영이 안 된 건지 캐시인지"를 즉시 구분하기 위해                    |
| `[contenthash]` 파일명       | 정적 자산을 안전하게 영구 캐시하기 위한 전제                          |
| index.html만 캐시 금지       | 배포했는데 화면이 그대로인 문제의 90%가 여기서 발생                   |
| `concurrency` 설정           | 연속 push 시 오래된 빌드가 최신 빌드를 덮어쓰는 사고 방지             |
| `paths: frontend/**`         | 문서만 고쳤을 때 불필요한 배포가 돌지 않도록                          |
| `API_BASE` 주입 분리         | 두 버전의 실질적 차이(오리진 분리 여부)가 코드에 드러나도록          |
